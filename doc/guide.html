MRI WLAB — User and Deployment Guide

Hirata Laboratory, NITech · the web app in APP_MRI/ · last updated 2026-10-23

1. Overview ↑ top

MRI WLAB is a small website of widgets: one page per tool, for viewing and processing MRI data — DICOM series, NIfTI and NRRD volumes, segmentations, surfaces, diffusion-weighted images and tractograms.

Most widgets run entirely in the browser: a file you open is read on your own computer and never uploaded. A few jobs are better done in Python (image registration, decoding compressed DICOM); those run in one local server, server.py, which also serves the pages.

2. Deploying ↑ top

2.1 Requirements

  • Python 3.10 or later with the packages in each <widget>/py/requirements.txt: gradio (5 or later; it brings fastapi and uvicorn), SimpleITK, nibabel, numpy, matplotlib.
  • dcm2niix for the server DICOM converter: on the PATH or at ~/bin/dcm2niix (github.com/rordenlab/dcm2niix). Without it the browser converter still works.
  • A current browser for the users: Chrome, Edge, Firefox, or Safari 16.4 or later. Volume 3D and Tract View need WebGL2 (hardware graphics).
pip install "gradio>=5" "SimpleITK>=2.3" "nibabel>=5" numpy matplotlib

2.2 Starting the server

  1. Go to the site's folder and start it: 
    cd APP_MRI
python server.py                       # http://127.0.0.1:8001/  (this computer only)
python server.py --port 8080           # another port
  2. Open http://127.0.0.1:8001/. The console lists every Python service it mounted (Service /py/registration, …). A service whose packages are missing is skipped with a warning; the rest still start.
One server runs everything: the pages and every widget's Python service, on one port. A widget never needs a server of its own.

2.3 Opening it to the lab network

python server.py --host 0.0.0.0 --port 8001
hostname -I                            # this computer's address, e.g. 192.168.1.20
sudo ufw allow 8001                    # if the ufw firewall is on

Others then open http://192.168.1.20:8001/, on a computer or a phone on the same network.

Only on a trusted network. The server has no login. Anyone who can reach the port can use the server widgets. Do not expose it to the internet.

2.4 Keeping it running

To keep the server running after you log out, run it under tmux/screen, or as a systemd service:

# /etc/systemd/system/mri-wlab.service
[Unit]
Description=MRI WLAB
After=network.target

[Service]
User=<your user>
WorkingDirectory=/home/<your user>/Documents/APP_MRI
ExecStart=/path/to/python server.py --host 0.0.0.0 --port 8001
Restart=on-failure

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload && sudo systemctl enable --now mri-wlab
journalctl -u mri-wlab -f              # its log

Files sent to the server widgets are kept in the system temp folder (/tmp/mri_wlab/<widget>/) and deleted after two hours. The uploaded DICOM is deleted as soon as it has been converted.

2.5 Without Python

The browser widgets need no server at all. Any static file server works (python -m http.server, nginx, a shared drive), and so does opening APP_MRI/index.html straight from the disk. What you lose:

  • Registration, Tractography and dcm2niix in DICOM → NIfTI: these pages say so and disable their button.
  • When the page is opened from the disk, Sample Data's Download all: download the files one by one instead.

3. Using the site ↑ top

3.1 Home page and menu

The home page shows every widget as a coloured tile, grouped by what it does (Viewing, Processing, dMRI, Resources). Type in Filter widgets… to narrow them down. A tile marked needs server.py works only when the site is served by server.py. In each group, these tiles come last. The Widgets ▾ menu in the top bar reaches any widget from any page.

3.2 How every page works

  • Sections fold away when you click their title (▾/▸). Secondary ones (Metadata, Export, Console) start folded.
  • Drop zones: drop files onto them, or click to choose. A DICOM series can be dropped as its folder (or Shift-click the zone to pick a folder). × clears the zone. A * marks a required input.
  • Tooltips: hover over a control's label for its explanation.
  • Results come as download links (several files also as one .zip), and are never written anywhere else.
  • Slices are shown neurological: the subject's left on the screen's left, anterior up (axial).
  • Hovering a slice shows the value under the cursor, with a crosshair linked across panels. A click locks the crosshair there, and another click (or Esc) releases it.

3.3 On a smartphone

Every page fits a phone screen: the two columns stack and wide rows wrap. In the 3D views, drag with one finger to rotate, and pinch with two to zoom or move them together to pan. Large files (a whole-brain tractogram, a big T1) can be slow on a phone. Tract View simplifies heavy tractograms automatically.

3.4 Where your files go

  • Browser widgets (everything except the three below): files stay on your device, in memory, and are gone when you close the tab.
  • Registration, Tractography and DICOM → NIfTI with dcm2niix: files are sent to the machine running server.py, processed there, and deleted (DICOM right away, results after two hours).
  • The DICOM converters write sidecars without the patient's name, IDs or birth date. Volume Slices shows the DICOM patient fields in Metadata and prints them on mosaics: check before sharing a mosaic.

4. The widgets ↑ top

Volume Slices browser

View a DICOM series, NIfTI or NRRD volume, with or without a segmentation, slice by slice.

Inputs
Image (DICOM files or folder, NIfTI, NRRD) · Segmentation (NIfTI, NRRD; 3D Slicer .seg.nrrd brings its names and colours) · Label names (CSV id,name[,r,g,b], ITK-SNAP, FreeSurfer / Slicer colour table).
Viewer
Axial / Coronal / Sagittal tabs and a slice slider. Range 1–99 % or full, colour map, brightness and contrast. The image appears beside the segments drawn over it.
Segments
Show or hide each one (fill, outline or both; opacity). Clicking a name highlights the segment and jumps to the slice holding most of it.
Export
A mosaic of the current plane as PNG or PDF. Set the grid (rows × columns) and the slices (auto, or indices such as 20, 34, 40-60). The metadata is printed underneath.
Notes
Image and segmentation are matched in world space, so their grids may differ. A segmentation saved with the image's matrix but a wrong header can be matched by voxel index instead. Compressed DICOM needs DICOM → NIfTI (dcm2niix) first.

Volume 3D browser

Render a volume in 3D, with its segmentation as surfaces and any VTK meshes.

Inputs
Volume (DICOM, NIfTI, NRRD) · Segmentation · Surfaces (legacy VTK; RAS unless tagged SPACE=LPS) · Label names.
Volume
Volume (ray-cast, with a window and opacity), MIP, Isosurface (with level and colour), or Off.
Surfaces
Each segment gets a smooth surface, with its own visibility and colour, a shared opacity and smoothing. Each VTK file gets its own colour, opacity and space.
View
Drag to rotate; right-drag or Shift-drag to pan; wheel or pinch to zoom; double-click to reset. A/P/L/R/S/I views, a clip plane, black or white background, a screenshot (PNG).

DICOM → NIfTI browser + server

Convert a DICOM study to one NIfTI per series.

Inputs
The study's files, its folder, or a .zip of it (any folder layout).
Converter
In the browser: uncompressed DICOM, nothing leaves the computer. The series are listed as soon as the files are dropped; untick what you do not want. dcm2niix (server): any DICOM (JPEG, JPEG 2000, RLE, mosaics).
Output
<series>_<protocol>.nii.gz and a .json sidecar per series (dcm2niix's field names, no patient identity), plus a zip of everything. Each series gets a role guess (T1 / T2, from its name and echo time); the best of each is starred.

Resampling browser

Resample volumes to an isotropic voxel size, keeping the field of view (the output overlays the input).

Inputs
One or several NIfTI / NRRD volumes · voxel size (0.1–10 mm) · interpolation (Auto, Nearest, Linear, B-spline) · To RAS.
How
Auto uses nearest-neighbour for a label map (an integer type with at most 256 values) and linear for an image. Images are smoothed first along any axis whose voxels grow, so they do not alias. "To RAS" reorders the axes without interpolating.
Output
<name>_<size>mm.nii.gz per file (and a zip). The viewer shows before and after side by side, with a table of both grids.

Registration server

Register a moving image (M) onto a fixed one (F), rigid or affine.

Inputs
Fixed image · moving image · optionally a segmentation of M (moved with it) · method (Rigid 6 DOF, Affine 12 DOF) · match F's voxel size / F's dimensions.
How
SimpleITK, Mattes mutual information (F and M may differ in modality), coarse to fine. The page streams the log while it runs; a typical brain pair takes 10–20 s.
Output
<M>_reg.nii.gz, <seg>_reg.nii.gz, a co-histogram figure, and transform.json (the 4×4 M → F transform in RAS mm). The viewer shows F in red and M in green, before or after.

Tract View browser

View whole-brain tracts within chosen segments, by direction.

On opening (site served by server.py), it shows the sample subject IXI034, simplified, as a demonstration: the input boxes stay empty, the other sections are locked, and the direction tabs and segment opacity are hidden. Loading your own tract file replaces the sample and unlocks everything.

Inputs
Tracts (VTK, PLY, TRK, TCK) · Head surface (VTK, PLY; RAS unless tagged) · Segmentation · Tissue names (optional; the sample's 14-tissue names are used until you drop others, or clear them).
Space
VTK and PLY files carry no coordinate frame unless tagged. Auto picks LPS or RAS, whichever puts the points in the white matter; you can also choose it yourself.
Segments
With tissue names, segments outside the brain (CSF, scalp, skin, bone, fat, eyes, humour, dura) are left out, and white matter, brainstem (midbrain, pons, medulla) and cerebellum start ticked, as does every segment with an id over 14 (listed whatever its name). Tick the ones to show tracts in: clipped to them, or passing through them.
Direction
Tabs All / L-R / A-P / S-I / Mixed, each as wide as its share of the tracts.
Simplify
Drop short tracts (100 mm), thin each bundle to a share (50 %), smooth; healing broken tracts is there to tick (off by default). On by default, so a heavy file never loads in full; untick it to show every streamline.
Viewer
The tracts in 3D, plus their projection on axial, coronal and sagittal planes (click one panel to move the other two planes), with the head surface around them (smoothed, its lower part fading out; a silhouette on the projections). Opacity of tracts, head surface and segments; how far the head fades out from below (Head fade, 0 = off); line thickness; colour by local direction or by class; Rotate (a slow turn; a drag stops it). For speed the lines are drawn with a point every 2 mm at most (tracking writes one every 0.875 mm; the drawn line stays within about 0.2 mm of it), and a whole-brain set is drawn as every k-th streamline while you drag or zoom, all of them again when you stop. The file and what is saved are not changed.
Output
The tracts shown, at full detail, as VTK (LPS, tagged) or TRK. The view and a tract / volume info sheet as a PDF or PNG; the sheet gives the simplification as its share ("50% tracts shown"), the page's Info section the full detail.

DWI 3D ⇄ 4D browser

Merge 3D DWI volumes into one 4D NIfTI, or split one into 3D files, choosing the volumes to keep.

Inputs
DWI volumes: several 3D NIfTIs (taken in natural name order, DTI-2 before DTI-10), one 4D NIfTI, or several 4D runs · Gradients: one .bval + .bvec (FSL) for all, one pair per file, or an MRtrix table. If the counts disagree, the page says so.
Choosing
Tick volumes, or whole shells. For b0s: keep all, keep the first, or average them into one. "Reduce each shell to n" keeps the n best-spread directions. A table shows each shell's smallest angle between directions and the tensor-fit condition number (about 1.5 is ideal).
Viewer
Gradients (default): the directions on a sphere, coloured by shell, optionally scaled by √b. Drag to turn it, and click a dot to keep or drop its volume. Axial / Coronal / Sagittal: the picked volume's slices.
Output
One 4D NIfTI, or 3D files named by a pattern: {name}, {index}, {n} (from 1), {source}, {frame}, {b}, zero-padded as {index:03}. For example, IXI034_dwi-{n:02}_b{b} gives IXI034_dwi-01_b0.nii.gz, and so on. Each comes with the matching .bval / .bvec.

Tractography server

Track whole-brain streamlines from a DWI series, with the lab's method (PROJ_DCONDNET b6_dti_wholebrain_tractography.py).

Inputs
DWI volumes: one 3D file per gradient (taken in file-name order), or one 4D file · the .bval and .bvec (FSL; told apart by shape) · FA threshold (0.2) · seeds per voxel (1) · step (0.875 mm) · minimum length (80 mm; the lab's b6 used 20) · brain mask (SynthStrip, the default, with its border, 1 mm; or the lab's b6; b6 when the server has no SynthStrip) · VTK and/or PLY · a simplified copy (on: ≥ 80 mm, 30 % at random, a point every 2 mm; made alike for every subject). Volumes beyond the b-values are left out, as the lab's preprocessing does (IXI's DTI-16, a QC image).
How
DIPY: a brain mask on the b0, either the lab's (Otsu, dilated 5 %) or SynthStrip's (FreeSurfer's skull stripping; the b6 mask's dilation takes in skull and scalp, whose noise gives a high FA, an outer ring in the tracking mask; SynthStrip leaves it out, and the eyes); a DTI fit (WLS), FA ≥ the threshold as the tracking mask; CSA-ODF peaks (SH order 6); deterministic tracking from seeds over the mask, stopping at its edge; short streamlines dropped; no streamline healed. The page streams the log; an IXI subject takes about 80 s.
Output
<subject>_wb_tracts.vtk (LPS, tagged) and/or .ply (RAS, tagged), <subject>_wb_tracts_simplified.vtk (when ticked), <subject>_brainmask.nii.gz. The viewer shows up to 20,000 of the streamlines in 3D, and the FA map with the tracking mask. Open the tract file in Tract View to explore it.

Brain Aging Demo browser

The two typical subjects of Nguyen, Kubota & Hirata, Age-related changes in brain fiber pathways based on directional decomposition of DTI tractograms, Neuroscience Informatics 6 (2026) 100255: IXI051 (25 y) and IXI518 (75 y), side by side.

Shows
Six tabs: the tracts in 3D (two views that turn together, a direction bar over each: shares on hover, a click filters both); axial, sagittal and coronal slices of both subjects on one grid (T1 or T2; tracts off, projected or their intersection with the slice; segment boundaries or fill over them; values on hover); and, for the ticked segments (the paper's four tissues at first), the tract density (tracts per cm³) and the direction composition (L-R, A-P, S-I, Mixed) as charts. Only the 3D tab's files load at first; the slices on their first visit.
Controls
Segments (clipped, passing through, whole head), direction, Tract View's simplification (folded; keep 20 %, ≥ 100 mm at first); per tab its own: underlay, tracts, segments, opacities, thickness. 💾 Save collects the current tab; Export writes the figures as a PDF (one per page, the paper cited at the end), or PNG.
Data
Built once by demo_brain_aging/prep/build_data.py: tracked in each subject's native space (FA ≥ 0.2, CSA-ODF, deterministic, 30°, 0.5 mm, ≥ 20 mm, whole brain), measured there (pieces ≥ 20 mm inside each segment), and shown in IXI051's b0 space (IXI518 registered affine). Unlike the paper, the whole brain is tracked once and cropped to the ROIs, so the densities are higher than the paper's, in the same order. The full list of differences is on the page and in demo_brain_aging/README.md.

5. A tour with the sample data ↑ top

  1. Sample Data → Download all, then unzip IXI034_sample.zip.
  2. Volume Slices: drop ana/IXI034_t1.nii.gz as the image and seg/IXI034_voxseg.nii.gz as the segmentation, plus seg/IXI034_labels.csv. Hover to read values, then open Export mosaic for a PDF.
  3. Volume 3D: drop seg/IXI034_voxseg.nii.gz and seg/IXI034_head.vtk; set the head surface's opacity to 0.3 to see the tissues inside.
  4. DWI 3D ⇄ 4D: drop all of dwi_processed/*.nii.gz, then IXI034_bval and IXI034_bvec. Look at the sphere, try Reduce each shell to 6, then write a 4D NIfTI.
  5. Tractography (with server.py): drop the same DWI files and gradients, tick PLY too, and press Run (about a minute: 88,196 streamlines). Open the VTK in Tract View.
  6. Tract View: drop tract/IXI034_wb_tracts.vtk, seg/IXI034_head.vtk, seg/IXI034_seg_match_dwi.nii.gz and seg/IXI034_labels.csv. Click the A-P tab, raise the thickness, then save the tracts or export the view as a PDF.
  7. Resampling: drop the T1 and choose 1 mm. Registration (with server.py): fixed = T1, moving = T2.

6. Troubleshooting ↑ top

What you seeWhy, and what to do
“… needs server.py: start the server …”The page was opened from the disk, or the server is down. Start python server.py and open the site from http://…:8001/.
Port already in useAnother server.py (or another program) holds the port. Stop it, or start with --port 8002.
“The DICOM pixel data is compressed …”The browser reads only uncompressed DICOM. Choose dcm2niix (server) in DICOM → NIfTI.
Tracts appear mirrored or off the brainThe tract file's space was misread. Set Tract space to LPS or RAS yourself.
“Gradients not used where they disagree”The .bval/.bvec has a different number of entries than the volumes (IXI's own tables list 16 for 17 raw volumes). Use a matching table.
A blank 3D view or “no WebGL2”The browser has no hardware graphics (remote desktop, an old browser). Use a current browser on a machine with a GPU.
A phone is slow with a large fileUse smaller files on phones, e.g. the simplified sample tractogram (Tract View also simplifies large ones itself).

7. Adding a widget ↑ top

The full rules are in APP_MRI/README.md. In short:

  1. Make a folder APP_MRI/<widget_id>/ with index.html, lib/ and asset/icon.svg. If it needs Python, add py/app.py exposing build(); server.py mounts it at /py/<widget_id>.
  2. Add one entry to common/registry.js, with a one-sentence description and server: true if it cannot run without Python.
  3. Put anything a second widget could use in common/.
  4. Check the page at 360 px and 768 px wide.
  5. Add a section for it to §4 of this guide, a row to the table in §1, a line to §8, and an entry to the contents list.
